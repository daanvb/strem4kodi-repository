# Stream loading review - 9 October 2026

The source picker now receives usable rows as each add-on completes, rather than waiting for the slowest add-on. It retains the selected source when later batches arrive and keeps filter focus steady. Search progress reports completed add-ons, returned links, pending add-on names, failures and rate limits; it does not invent a percentage or completion estimate. A failed search keeps links already received available for manual selection.

Fresh saved stream results can open the picker immediately. Explicit Refresh bypasses saved rows. Existing disk-cache limits remain 15 minutes fresh and 24 hours maximum retention. Title-open format checks and source selection share an overlapping search within the same Python runtime, including replay of already-arrived results. The sharing key includes device profile, media type, target identity and enabled provider configuration. Completed jobs are removed; the ordinary device-local stream cache stores results. This is distinct from the shared format database and does not share playable links across devices.

Automatic selection has no result-count threshold or new setting. Under Recommended ordering, an exact preference match at a known target resolution starts without an artificial settling pause. Any prefers 1080p, with 720p and lower resolutions as fallbacks and 4K as a last resort; explicit 4K remains supported. With a 720p device ceiling, 720p is the early target. Fallbacks wait for the completed search to avoid choosing them while HD is still pending. Maximum quality, provider, audio, video, language and picker filters continue to apply. Reported metadata is required for matching; unknown language or quality does not count as an exact match. The asynchronous callback reassesses the latest rows before playback.

Repeated URLs are deduplicated for early selection; identical release filenames and technical metadata use the existing conservative release grouping. Duplicate counts never trigger playback. Alternate links remain available for recovery. Explicit provider ordering and smallest/largest sorting wait for all results. Resuming a title with a saved successful-source fingerprint waits for that release before early playback; a saved UHD release does not override Any's HD preference. Ordinary full-results resume selection remains available if the saved release does not arrive. Up Next uses the same early-match rule and retains its Loading card; an early failed probe counts against the existing automatic retry limit.

Back, dismissal, a new search generation and window shutdown block late callbacks from starting playback or reopening the picker. Already-running provider HTTP requests are allowed to finish, so their results can populate local caches; dismissal is not claimed to refund a provider token. No extra speculative browsing searches, video downloads or stream-link probes are introduced by this change. Provider parallelism and network timeouts remain unchanged. There is no guaranteed two-second startup: add-on response time, link resolution and player buffering remain external dependencies.

The playback overlay uses a compact card over dimmed existing title artwork, the app's purple accents, clear Starting playback text and a slower-source message with an alternative-source suggestion. Automatic searches open this card immediately, keep source rows hidden and hand over to the playback stage with the same artwork/trivia. Manual searches retain the source picker. Cancel uses a solid rounded pill. The card shows no startup timer. Existing attempt ownership, cancellation and cleanup safeguards remain.
